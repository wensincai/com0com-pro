# com0com-pro 使用指南

> 适用版本：0.3.0（P1–P6 全部完成）
> 本文回答两个最常见的入门问题：「setupc.exe 未找到是什么意思」和「我该怎么把这套系统跑起来」。

---

## 1. 系统组成

com0com-pro 由两部分组成：

| 部分 | 形态 | 作用 |
|---|---|---|
| **com0com 内核驱动**（`com0com.sys`） | Windows 内核驱动 | 在系统中创建**成对的虚拟串口**（如 CNCA0 ↔ CNCB0），写进一个口的数据会从另一个口出来 |
| **ccp 工具链**（用户态 Rust 程序） | `ccp.exe` / `ccp-gui.exe` / `ccp-service.exe` | 在虚拟串口之上做**捆绑路由**：一条串口数据可以同时发给多个设备（split）、多路汇合（merge）、多应用共享一个口（share）、双向转发（redirect），并提供配置、活动日志、开机自启 |

关键理解：**ccp-gui 本身不创建虚拟串口**。虚拟串口是内核驱动提供的；GUI 只是"调度室"。所以驱动没装时，GUI 会提示找不到 `setupc.exe`——这是正常现象，不是软件坏了。

## 2. 「setupc.exe 未找到（未安装 com0com）」是什么意思

GUI 启动时会在以下两个固定路径查找 com0com 的配置工具：

```
C:\Program Files (x86)\com0com\setupc.exe
C:\Program Files\com0com\setupc.exe
```

两处都找不到，说明 **com0com 虚拟串口驱动没有安装到系统**（你手上的源码只是编译出了 `com0com.sys`，编译 ≠ 安装）。没有驱动就没有 CNCA0/CNCB0 这类虚拟端口，"端口对"区域自然是空的。

**解决方法见第 3 节。** 在装好驱动之前，你仍然可以用 `tcp://` 端点体验 bundle 路由功能（见第 5.1 节）。

## 3. 正确的安装步骤

### 3.1 推荐方式：用 NSIS 安装包（一次到位）

以管理员身份运行：

```
installer\com0com-pro-setup.exe
```

组件勾选建议：

| 组件 | 是否勾选 | 说明 |
|---|---|---|
| ccp 工具链 | ✅（必选） | ccp.exe / ccp-gui.exe / ccp-service.exe |
| com0com driver (x64) | ✅ | 把 com0com.sys + setupc.exe 装进系统，并自动执行驱动预安装 |
| Start Menu Shortcuts | 按需 | 开始菜单快捷方式 |
| Register bundle service | 可先不勾 | 开机自动重建 bundle；建议先用 GUI 调通配置后再注册 |
| Create port pair CNCA0<->CNCB0 | ✅ | 装好驱动后立刻创建第一对虚拟串口 |

安装完成后：设备管理器 →「端口 (COM 和 LPT)」应出现 **CNCA0** 和 **CNCB0** 两个端口；`C:\Program Files (x86)\com0com\setupc.exe` 存在，GUI 的警告随之消失。

### 3.2 官方签名驱动路线（默认组件）——**Secure Boot 开启时不可用（实测结论）**

安装器默认安装的是官方 `com0com-3.0.0.0-i386-and-x64-signed.zip` 中的 CyberCircuits 签名驱动。
它内嵌了 Microsoft Code Verification Root 交叉证书，Authenticode 校验"有效"，**但交叉证书签发于
2015-12-31（终端证书 2016-01-04），晚于微软 2015-07-29 内核交叉签名政策截止日**。因此：

- Secure Boot **开启**：内核一律拒绝加载，设备管理器报 `Code 52`（`CM_PROB_UNSIGNED_DRIVER`），
  与 HVCI 开关无关。这是社区公论（com0com SourceForge 论坛 / com0com.com 官方指南），无免费解法。
- Secure Boot **关闭**：该驱动在大多数机器上可正常加载（个别随升级装机的系统例外）。

排查口诀：设备管理器里 com0com 设备出现**黄色感叹号 + Code 52** = 签名策略拒绝，先查 Secure Boot；
设备节点**压根不存在**（连感叹号都没有）= 端口对组件没装/没创建，重跑安装器勾选
「Create port pair」或手动执行 `ccp pair ensure 0`（需管理员，且注意 setupc 按**当前工作目录**
解析 INF——建议在安装目录下运行）。

### 3.3 P5 测试签名驱动路线（可选组件）

本项目编译的驱动是**测试签名**（自签名证书 `CN=com0com Test`）。默认配置的机器上有两道拦截：

**拦截一：安装阶段**（症状：`SetupCopyOEMInf ERROR: 0x800B0109 - certificate chain ... not trusted`，以及 `UpdateDriverForPlugAndPlayDevices ERROR: 265`）

原因：`com0com.cat` 的签名证书不在系统的受信任存储里。新版安装器已自动执行证书安装（`certutil -addstore Root / TrustedPublisher com0com-test.cer`）；如果你看到这两个报错说明装的是旧版安装包——重新用新版 `com0com-pro-setup.exe` 安装即可，或手动执行：

```bat
certutil -addstore Root "C:\Program Files\com0com-pro\com0com-test.cer"
certutil -addstore TrustedPublisher "C:\Program Files\com0com-pro\com0com-test.cer"
```

**拦截二：内核加载阶段**（即使证书装好了，驱动仍可能无法启动）

需要同时满足：开启测试签名模式 + 关闭 HVCI（内存完整性）。管理员命令提示符：

```bat
bcdedit /set testsigning on          :: 允许测试签名内核驱动（重启生效）
```

关闭内存完整性：**Windows 安全中心 → 设备安全性 → 内核隔离 → 内存完整性 → 关**，然后重启。

验证状态（管理员 PowerShell）：

```powershell
bcdedit /enum "{current}"    # 看 testsigning 行（无此行 = 未开启）
(Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity").Enabled   # 1 = HVCI 开，须为 0
```

重启后再次运行安装器（此时证书已装、签名模式已开、HVCI 已关），`setupc preinstall` 应能成功创建端口对。

> 注意：开着测试签名模式时，桌面右下角会显示"测试模式"水印，属正常现象；想恢复原状时 `bcdedit /set testsigning off` 并把内存完整性开关打开即可。
>
> **总结（2026-11 实测）**：无论走官方签名驱动还是 P5 测试签名驱动，都需要**先在 BIOS 关闭 Secure Boot**——前者被 2015-07-29 交叉签名截止日挡住，后者被测试签名策略挡住（`bcdedit /set testsigning on` 会报 "The value is protected by Secure Boot policy"）。关闭 Secure Boot 后：官方签名驱动通常直接可用；想用 P5 强删增强驱动则再开 testsigning。

## 4. 核心概念（2 分钟）

- **端点（Endpoint）**：一根"串口线头"。类型三种：
  - `COM3` / `CNCA0` —— 本机串口（虚拟或物理）
  - `tcp://192.168.1.10:5000` —— TCP 网络端点
  - `pipe:名字` —— 命名管道（规划中，暂未实现）
- **捆绑（Bundle）**：把若干端点组织成一个数据流拓扑：
  - **Redirect**：1 进 1 出，双向转发（A 口写的字从 B 口出，反之亦然）
  - **Split**：1 进 N 出，数据复制到每个出口
  - **Merge**：N 进 1 出，多路汇成一路
  - **Share**：N 进 N 出同端点，多应用共享一个串口（读复制 + 写仲裁）
  - **Complex**：多进多出
- **策略（Policy）**：多个出口时数据怎么发：`copy-all`（默认，全部复制）/ `round-robin`（轮流）/ `one-to-one`（按序配对）/ `first-writer-wins:毫秒`（抢写）

配置持久化在 `C:\ProgramData\com0com-pro\bundles.json`。

## 5. 三种典型用法

### 5.1 无驱动体验：TCP 环回（装驱动前就能玩）

用两个网络调试工具（或 `ncat`）各连 `127.0.0.1:9001` 和 `9002`，创建 Redirect bundle：

```
名称: tcp-link   类型: Redirect
inlets:  a:tcp://127.0.0.1:9001
outlets: b:tcp://127.0.0.1:9002
```

在 GUI 中点 **▶ 启动引擎**：从 a 写入的数据会出现在 b，反之亦然。底部活动日志实时显示每次写入。

### 5.2 标准玩法：两个 Windows 应用互连（模拟串口线）

装好驱动（第 3 节）后：

1. GUI 左侧 **＋ 新增** → 类型 `Redirect`，端点填 `app1:CNCA0` / `app2:CNCB0`
2. **保存配置** → **▶ 启动引擎**
3. 把两个应用的串口参数分别设为 CNCA0 / CNCB0（相同波特率），即可互相收发
4. 需要更多端口对：GUI 端口对区域调 setupc，或 `ccp pair ensure 1` 创建第 2 对

典型场景：给只有串口的老设备调试工具"喂"回放数据、串口协议联调、GIS/雷达设备仿真（GeoPro 场景）。

### 5.3 一串口分发给多应用（Split/Share）

GPS 模块接在真实 `COM3`，两个软件都要读：

```
名称: gps-split   类型: Split
inlets:  gps:COM3
outlets: app-a:CNCA0
         app-b:CNCA1
策略: copy-all
```

两个应用分别打开 CNCA0/CNCB0…… 对应的虚拟口即可。`Share` 模式则不需要虚拟口分发，直接多应用开同一个口。

## 6. GUI 操作速查

| 操作 | 位置 |
|---|---|
| 启动/停止全部 bundle | 顶部工具栏 ▶ / ■ |
| 新增/删除 bundle | 左栏 ＋ 新增 / － 删除 |
| 编辑端点 | 中间编辑区，每行一个 `名字:目标`（TCP 写 `名字:tcp://host:port`） |
| 校验配置 | 编辑区「校验配置」按钮 |
| 保存到 bundles.json | 顶部「保存配置」 |
| 查看实时活动 | 底部「活动日志」面板（引擎运行中每 0.5s 刷新） |
| 刷新串口/端口对列表 | 顶部「刷新端口」或勾选「自动刷新」 |

注意：**改动端点后必须点「应用修改」再重启引擎**才生效；bundle 运行中 ▶ 按钮是禁用状态，先 ■ 停止再启动。

## 7. 命令行速查（ccp.exe）

```bat
ccp init bundles.json              :: 生成示例配置
ccp validate bundles.json          :: 校验拓扑（退出码 0/2）
ccp ports                          :: 枚举本机物理串口
ccp list                           :: 列出 com0com 端口对
ccp pair list                      :: 同上（走 PairManager）
ccp pair install 2                 :: 创建第 2 对端口（CNCA2<->CNCB2）
ccp pair ensure 2 --a EmuBR=yes    :: 幂等确保端口对 2 存在且带指定参数
ccp pair remove 2                  :: 删除端口对
ccp serve bundles.json             :: 前台运行全部 bundle（Ctrl+C 停止）
ccp service install                :: 注册并启动 ccp-service（开机自动重建）
ccp service status / uninstall     :: 服务状态 / 卸载
```

## 8. 故障排查

| 现象 | 原因与处理 |
|---|---|
| GUI 提示找不到 setupc.exe | 驱动未安装 → 第 3 节；装了官方版但路径不同 → 确认在 Program Files 下 |
| 点了启动引擎无数据 | ① 端点名拼错（改完要点「应用修改」）；② 串口被别的程序独占；③ 看底部活动日志有无 error 事件 |
| 驱动装不上 / 端口对不出现 | HVCI 或测试签名拦截 → 第 3.3 节 |
| `ccp serve` 报 open failed | 端口不存在或被占用；TCP 端点检查地址可达 |
| 服务注册了但不跑 | `%ProgramData%\com0com-pro\bundles.json` 不存在或为空；先在 GUI 里「保存配置」 |
| 想强删被占用的端口对 | 驱动实验开关 `ForceRemoveOpenPorts`（默认关），见 docs/05-驱动增强说明.md |
| GUI 中文是方块 | 用 0.3.0 之后的版本（已内置微软雅黑加载） |

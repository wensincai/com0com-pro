# 07 — 遗留问题与已知限制（2026-11-24 项目告一段落快照）

本文档记录 com0com-pro 截至当前版本的**全部未决问题**。这些问题不影响已交付功能的使用，
但如果把本产品分发给他人使用，会碰到几乎一样的坑——分发前务必阅读本文。

## 1. 驱动签名（最关键，直接影响所有用户）

### 1.1 Secure Boot 开启的机器上，产品无法工作

- **现象**：设备管理器中 com0com 设备报 `Code 52 (CM_PROB_UNSIGNED_DRIVER)`，端口形同虚设。
- **根因（已实测验证）**：
  - 官方签名驱动（安装器默认组件）：CyberCircuits 交叉证书签发于 2015-12-31，
    晚于微软 2015-07-29 内核交叉签名政策截止日。Secure Boot 开启时内核一律拒绝，
    HVCI（内存完整性）关闭也无效。社区结论一致（com0com SourceForge 论坛、com0com.com 官方指南）。
  - P5 测试签名驱动（可选组件）：需要 `bcdedit /set testsigning on`，而 Secure Boot
    开启时该设置被锁定（"The value is protected by Secure Boot policy"）。
- **影响**：只要用户没关 Secure Boot（现代预装 Windows 的默认状态），本产品装完即"看不见端口"。
- **当前解法**：BIOS 关闭 Secure Boot。官方签名驱动多数机器可直接加载；P5 增强驱动需再开 testsigning。
- **根治方向（未实施）**：
  1. 将修改后的驱动提交微软硬件开发中心做 **attestation 签名**（需 EV 代码签名证书 + 硬件提交流程，
     费用约数百美元/年），产出可随 Secure Boot 加载的驱动包；
  2. 或在产品分发页明确前置条件："需关闭 Secure Boot"。

### 1.2 P5 强删增强驱动长期处于"测试签名"状态

- 驱动源码在 `E:\reverseEngineering\20261112\com0com\sys\`（build.cmd 编译通过），
  与 1.1 绑定：无 attestation 签名前，只在 testsigning 机器上可用。
- 若走 attestation 路线，P5 的 `ForceRemoveOpenPorts` 延迟移除逻辑需重审
  （ObReferenceObject/IoAllocateWorkItem 的引用计数与回调时机）以符合 WHQL 质量门槛。

## 2. 安装器 / 工具链

### 2.1 setupc 的 INF 解析依赖当前工作目录（已绕过，未根治）

- com0com 原始代码 `setup/inffile.cpp GetFilePath()` 用 `GetFullPathName("com0com.inf")`
  按 **CWD** 解析 INF。我们在 `pair.rs run()` 中固定了 `current_dir`，但：
  - 任何第三方代码直接调用 setupc.exe 时仍会踩坑（如从任务计划程序启动，CWD 为 system32）；
  - 根治需改 com0com setup 源码（把 INF 解析锚定到 exe 所在目录），随 attestation 驱动一并提交上游。

### 2.2 setupc 无静默的机器可读错误码

- 所有失败都以退出码 1 + 弹窗呈现，`--silent` 只压掉弹窗。ccp 只能靠解析 stdout 文本猜测失败原因。
- 改进方向：PairManager 增加结构化错误分类（权限不足 / INF 缺失 / 端口占用 / 签名拒绝），
  GUI 据此给出针对性指引（本产品分发后，用户最需要的就是这一层）。

### 2.3 安装/端口对操作需要管理员权限

- setupc 全部命令需提权。GUI 直接调用 setupc，普通权限运行 GUI 会让 pair 操作全部失败
  （目前 GUI 仅在启动自检时提示 setupc 缺失，未提示权限不足）。
- 改进方向：GUI 检测到非提权会话时提示"以管理员身份运行"；或把 pair 操作挪进 ccp-service（SYSTEM 账户）。

### 2.4 卸载残留

- `setupc infclean` 对已存在的 oem*.inf 返回 `FAILURE(0x00000050)`（file exists），
  残留旧 INF（如 oem74/oem108，签名者 "com0com Test"）可能被系统优先选中，导致新设备安装失败。
- 用户侧自查命令：`pnputil /enum-drivers | findstr /i "com0com cncport comport"`。
- 改进方向：安装器在驱动节前主动枚举并 `SetupUninstallOEMInf` 掉旧版本 INF。

## 3. 功能缺口（对照 VSPD 差距矩阵，P6+ 未实施项）

| 项目 | 状态 | 说明 |
|---|---|---|
| Pipe 端点（命名管道） | 未实现 | config.rs 已有 EndpointKind::Pipe 占位，host.rs 无实现 |
| JSON-RPC 控制 API | 未实现 | 服务目前仅支持 bundle 重建，无远程管理通道 |
| ACL 强制（按用户授权端口访问） | 未实现 | VSPD 的核心付费卖点之一 |
| 按会话动态创建/销毁端口对 | 未实现 | 需改驱动；当前只有 setupc 级静态 pair |
| TCP 端点 E2E 测试 | 被忽略 | `#[ignore]` 标记（沙箱禁止监听），需实机验证 |
| 性能压测（高波特率/长时间） | 未做 | 泵线程架构未经基准测试 |

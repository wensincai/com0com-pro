## 2. 驱动 sys/ 深度分析

### 2.1 架构模型

com0com 用 **bus FDO + 端口 PDO** 的 WDM 模式：

- 总线设备（`com0com - bus for serial port pair emulator`）由 `adddev.c` 动态枚举出成对的端口子设备
- 每个端口是标准串口 PDO，向 PnP 暴露 `CNCAn`/`CNCBn` 或 COMx 设备接口，应用用 `CreateFile("\\\\.\\CNCA0")` 打开
- **端口对通过内存直连**：`C0C_IO_PORT.pIoPortRemote` 双指针互指，write 侧把数据放入对端 read 队列——零拷贝跨口、无缓冲文件、无事件环
- 配置存注册表 `HKLM\SYSTEM\CurrentControlSet\Control\com0com`（pairs/参数），PnP 持久化 → 重启自动重建（对齐 VSPD 同能力）

### 2.3 扩展 IOCTL 面（include/cncext.h，供用户态引擎调用）

- `IOCTL_SERIAL_LSRMST_INSERT` 扩展：`C0CE_INSERT_ENABLE_RBR`（插入对端波特率）/`RLC`（对端线控）/`LSR_BI`（BREAK 变化插入）→ 引擎可**监视**对端配置，实现 VSPD 式"活动日志 + 参数感知"
- `IOCTL_SERIAL_SET/GET_MODEM_CONTROL`：逐脚（含 OUT1/OUT2）读写
- 插入开关走 `c0c` 签名块（`C0CE_SIGNATURE "c0c"`）

## 3. 用户态组件分析

### 3.1 setup/（setup.dll，6,997 行）——最值得研究的复用对象

| 模块 | 内容 |
|---|---|
| `params.cpp` | 端口参数模型：`PortName/RealPortName/EmuBR/EmuOverrun/PlugInMode/ExclusiveMode/HiddenMode/AllDataBits/cts/dsr/dcd/ri/EmuNoise/AddRTTO/AddRITO`（GetBitName 全集） |
| `comdb.cpp` | COM 口号数据库（占用表，防冲突分配） |
| `devutils.cpp` | SetupAPI 设备安装/卸载/更新驱动 |
| `inffile.cpp` | INF 解析（UninstallInfTag 自定义字段） |
| `portnum.cpp` | Ports class 自动选号（`PortName=COM#` → RealPortName） |
| `setup.cpp` | 命令解析：install/remove/change/list/update/monitor 等 |
| `msg.cpp`/`utils.cpp` | 输出与杂项 |

- **问题**：`MainA` 为唯一导出，内部紧耦合（参数解析、设备操作、输出混在一起），不适合直接作为编程 API
- **决策**：不在其上扩展；改为新控制面通过 **子进程调用 setupc.exe**（稳定契约）+ 必要处直接走 SetupAPI（Rust/windows crate）实现 install/remove，避免 GPL C++ 深度绑定

### 3.2 setupc/setupg

- setupc 51 行薄壳，无逻辑 → 保留作为驱动管理的事实标准
- setupg 单 43KB Form1.h 的 .NET WinForms 表格 UI → 不复用，新 GUI 用 egui 重写（拓扑视图 + 实时监视）

## 4. 复用/改造/新建清单

| 部分 | 决策 | 理由 |
|---|---|---|
| `sys/` 全部 | **原样复用** | 0 warning 编译通过、功能强于预期（pinout/noise/插入监视都有） |
| `setupc.exe` | **外部依赖保留** | 命令契约稳定；新控制面以子进程+解析 stdout 方式调用 |
| `setup.dll` 内部逻辑 | **参考实现** | comdb 选号、设备安装流程照抄语义，不链其二进制 |
| `setupg.exe` | **弃用** | .NET WinForms 与新栈不符 |
| bundle 引擎 | **新建**（Rust） | VSPD 差距全在此；用户态事件驱动路由 |
| 活动/ACL/服务/日志 | **新建**（Rust） | — |
| GUI | **新建**（egui） | 复用 putty-rs 的 GUI 工程经验 |
| NSIS 安装包 | 后续迁移 | 路径需改 x64；P4 再做 |

## 5. 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| GPL v2 传染 | 中 | 全项目 GPL v2+；新代码不链接 setup.dll 闭源产物（其本就是 GPL，无闭源问题，但避免 C++ 深耦合） |
| 驱动加载受限（HVCI/Secure Boot） | 高（本机） | 测试进关闭 HVCI 的 VM；用户态引擎可用真实 COM/命名管道先行开发 |
| setupc stdout 契约脆弱 | 中 | 封装层做输出解析回归测试；关键操作改走 SetupAPI 直调 |
| setupg 弃用后老用户无 GUI | 低 | P4 GUI 交付前保留 setupg 可选构建 |

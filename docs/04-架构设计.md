# com0com-pro：架构设计

- 日期：2026-11-23

## 1. 总体架构

```
┌─────────────────────────── 用户态（新增，Rust）───────────────────────────┐
│  ccp-gui（egui）      ccp-cli（ccp.exe）          第三方程序              │
│        │ JSON-RPC / 命名管道   │                    │ ccp-core API       │
│        └──────────────┬───────┴────────────────────┘                   │
│                       ▼                                                │
│              ccp-service（引擎宿主/服务）                                │
│   ┌──────────────────────────────────────────────────────────┐         │
│   │ ccp-core:                                                │         │
│   │  PairManager ── 调 setupc.exe 安装/删除/改参数/列端口对     │         │
│   │  BundleEngine ─ 拓扑引擎（split/merge/share/redirect/complex）│      │
│   │  Endpoint ──── 端点抽象：SerialEndpoint / PipeEndpoint /  │         │
│   │                 MemoryEndpoint(测试)                      │         │
│   │  ActivityLog ── JSONL 活动/审计日志                        │         │
│   │  Config ────── bundles.json 持久化 + 开机重建             │         │
│   └──────────────────────────────────────────────────────────┘         │
└────────────────────────────────────────────────────────────────────────┘
                                │ CreateFile(\\.\CNCA0 …)
┌─────────────────────────────── ▼ （复用，不动）──────────────────────────┐
│              com0com.sys（WDM：端口对、pinout、流控、噪声、监视插入）      │
└────────────────────────────────────────────────────────────────────────┘
```

设计要点：

- **控制面/数据面分离**：bundle 数据泵只在服务进程；GUI/CLI 只发控制指令 → 引擎崩溃/重启不丢驱动侧配置（NFR-4）
- **端点抽象**：统一 `async Read/Write` + `open/close/lines()` 接口；`MemoryEndpoint` 使路由引擎在 CI 全速单测
- **setupc 外部契约**：PairManager 只做子进程调用 + stdout 解析 + 幂等重试；解析器有回归单测

## 2. BundleEngine 拓扑模型

```rust
pub enum BundleKind { Split, Merge, Share, Redirect, Complex }

pub struct BundleSpec {
    pub name: String,
    pub kind: BundleKind,
    pub inlets: Vec<EndpointSpec>,   // 数据源侧
    pub outlets: Vec<EndpointSpec>,  // 数据消费侧
    pub policy: RoutePolicy,         // 分发/仲裁策略
    pub acl: Option<PortAcl>,        // FR-A3
}

pub enum RoutePolicy {
    CopyAll,                 // split 默认：每条入站复制到全部 outlet
    RoundRobin,              // merge 轮转
    FirstWriterWins,         // share 写仲裁
    Match(FuncId),           // complex：按规则函数路由（P4+）
}
```

运行时结构：每 endpoint 一个 tokio pump task（`spawn_blocking` + serialport 阻塞读），经 `mpsc`/`broadcast` 通道进入路由核心；路由核心是纯函数状态机（可单测）：

```
        ┌── pump(inlet A) ─┐
数据 ──►│                  ├──► Router{RoutePolicy} ──► outlet pumps ──► 端口
        └── pump(inlet B) ─┘
```

## 3. 活动日志与 ACL

- ActivityLog：JSONL（时间、bundle、端点、事件 open/close/read(n)/write(n)/line-change/error），按日滚动，查询 API 按 bundle/端点/时间过滤
- PortAcl：`allow: {process, access: read|write|both}` 列表；服务在引擎侧代开端口（引擎持有 handle，应用直连引擎命名管道）→ P4 之前 ACL 仅审计记录（deny 不可强制，如实记录）

## 4. 服务生命周期

1. 安装 `ccp-service`（SCM，LocalSystem）
2. 启动：读 `bundles.json` → 逐 bundle：PairManager 确保端口对存在（幂等，缺失则 `setupc install`）→ 起 pump
3. 运行：命名管道 `\\.\pipe\ccp-ctl` JSON-RPC：`status/list/pair/bundle/log/stop`
4. 停止：逐 bundle 撤泵（drain → close），配置不删除

## 5. 目录结构

```
com0com-pro/
├── docs/                本文档系列
├── crates/
│   ├── ccp-core/        端点抽象、路由引擎、配置、日志、PairManager

```

## 6. 测试策略

| 层 | 方式 |
|---|---|
| 路由核心 | MemoryEndpoint 单测：split 复制、merge 轮转、share 仲裁、redirect 双向、断开重连、背压 |
| PairManager | setupc stdout 解析回归；`--dry-run` 契约测试 |
| E2E（VM 内） | 装驱动 → `ccp bundle` 建 split → 两个应用互通；活动日志核对字节数 |
| 性能 | 1 MB/s×60s 稳态吞吐 + CPU 采样 |

## 7. 里程碑对应实现顺序

P2 = ccp-core（MemoryEndpoint + Router + Config + Log，单测全绿）→ P3 = SerialEndpoint + PairManager + CLI → P4 = service + GUI → P5 = 驱动小改。

## 8. 实现状态（P5 完成后）

| 层 | 实现 | 位置 |
|---|---|---|
| 端点 | Serial（serialport 4.x，阻塞读 + 100 ms 超时）、Tcp、Memory（测试） | `ccp-core/src/host.rs` |
| 泵 | 每端点一线程：读设备 → `mpsc` → 引擎；引擎写 → 命令通道 → 线程写设备 | `host.rs::spawn_pump` |
| 引擎 | `BundleEngine` + `Router`（4 策略），事件回调写 JSONL | `engine.rs` / `router.rs` |
| 端口对 | `PairManager`（setupc.exe 子进程，幂等 ensure/remove） | `pair.rs` |
| 配置 | bundles.json（`SessionConfig`），类型校验在保存/加载/启停前 | `config.rs` |
| 服务 | `ccp-service`：SCM 生命周期 + 控制处理 + `%ProgramData%\com0com-pro` | `crates/ccp-service` |
| GUI | `ccp-gui`：bundle 编辑、引擎启停（进程内）、活动日志 tail、端口列表 | `crates/ccp-gui` |
| 驱动 | ForceRemoveOpenPorts（默认关）延迟移除 | `com0com/sys/{pnp,openclos,adddev,read,write}.c` |

已知偏差（与本文档原计划的差异）：

1. **Pipe 端点未实现**：`EndpointKind::Pipe` 仍返回配置错误，命名管道 + JSON-RPC 控制接口推到 P6；
2. **GUI 进程内跑引擎**：未做控制面/数据面拆进程（FR-A6 的 JSON-RPC），单机场景够用；
3. **ACL 仅配置不强制**：引擎不代开句柄，无法在打开时拒绝；记录能力已具备。
